GenesisWorkbenchEnv: fix an object’s physics from one complaint

A sim-ready object comes out of a VLM-to-CAD step with a physics bug. A contributor says what feels wrong, and that sentence is the whole task prompt. An LLM agent works out the cause and edits the object through MCP tools while Genesis simulates and renders it. When the agent stops, a probe suite it never sees runs the edited object in Genesis and compares its behaviour with a reference.

The agent getsA complaint and an object

One MJCF file with one physics bug from the CAD step, and a contributor’s sentence about how it misbehaves. Nothing says which parameter is wrong.

It can useSeven MCP tools

inspect, render (returns PNG frames), set_inertial, set_material, set_joint, run_probe and diff, all backed by a live Genesis scene.

It is graded byA hidden probe suite

Genesis runs the edited object through the task’s probe (tilt table, hinge swing or drawer pull) and checks it against reference behaviour, for a score from 0 to 1 and a pass or fail.

How an episode runs

The agent loops through steps 2 to 4 as many times as it wants: it calls a tool, Genesis answers with numbers or rendered frames, and the agent edits again. The probe suite runs once, after the agent’s last turn.

Episodes

One tab per task. Each shows the complaint, every tool call the agent made with the frames Genesis rendered, the hidden probe’s curves before and after the edit, the checks, and the MJCF diff.

What the agent changed

The CAD export wrote the inertial frame at the body origin. The fix recomputes it from the ceramic shell; nothing about the shape changes.

inspect()body: ceramic · 0.284 kg · COM z 0.3 cm
set_inertial(link="body", from_material="ceramic")0.284 kg · COM z 3.95 cm
run_probe(kind="tip")topples from 43° on the tilt table · statics say 45.4°

The demo uses the rigid-body tipping rule, not Genesis: a body released at a lean falls once its centre of mass passes the edge it pivots on, at atan(radius ÷ COM height). With a 4 cm radius that is 85.7° before the fix and 45.4° after.

Run it yourself

The plugin installs into an agentenv-framework environment and ships a bundle named genesis-workbench with eleven tasks: three on objects built from primitives and eight on real assets (scanned objects, VLM-to-CAD output and ReplicaCAD furniture). Genesis runs on its CPU backend, so no GPU is needed.

# install agentenv-framework, then add the plugin
agent-env plugin add 'agentenv-genesis @ git+https://github.com/earakely-scale/agentenv-genesis-plugin'

# run all eleven tasks
agent-env run genesis-workbench

Claude Code needs a model endpoint that serves Anthropic’s Messages API, set in [model] of .agentenv/config.toml. Every run is recorded in agentenv’s local store.

  • mug-tipThe inertial frame of mug_017 sits at its base. Probe: a tilt table, final tilt for each lean angle.
  • oven-doorA 1.2 kg door with 4.0 N·m of hinge friction never opens. Probe: hinge angle over time after release at 5°.
  • drawer-slideThe drawer has no joint at all. Probe: drawer travel over time under a 10 N pull.

GenesisWorkbenchEnv is a prototype: eleven tasks, three objects built from primitives and eight real assets with defects found by an asset audit, and probe tolerances and weight bands that are our estimates. The plugin, this viewer and the episode data are Apache-2.0, as is Genesis.
